# Plan 07-05 — BOQ per-line value display (gap closure for SC2)

<objective>
Close the gap between requirement COST-02 ("system computes BAC/EV") and roadmap Phase 7 Success Criterion #2 ("the BOQ view SHOWS contracted value (BAC) and earned value (EV) per line item"). The compute layer exists in analytics.ts; this plan surfaces per-line value in the BOQ table. Per-line value is self-contained from each row's existing fields (unitPrice, currencyCode, plannedQty, approvedQty) — do NOT call getProjectMetrics (that is project-level currency-grouped totals for Phase 9). Money math at the display layer uses decimal.js (never raw JS float multiply), honoring the milestone locked decision.
</objective>

<task id="1" type="execute">
<action>
Create `src/lib/boq-value.ts` exporting two pure helpers:
- `lineValue(qty: string | null | undefined, unitPrice: string | null | undefined): string | null` — returns `new Decimal(qty).times(unitPrice).toFixed(2)` when both are present and numeric, else `null`. Use `decimal.js` (already installed) — never `parseFloat(...) * ...`.
- `formatCurrency(value: string | null, currencyCode: string | null | undefined): string` — when value is null returns the em-dash placeholder `—`; otherwise formats with `new Intl.NumberFormat('tr-TR', { style: 'currency', currency: currencyCode || 'TRY' })`. Guard against an invalid currency code by falling back to a plain number + code suffix in a try/catch.
BAC uses plannedQty; EV uses approvedQty.
</action>

- src/components/dashboard/BoqTable.tsx (BoqItem shape: plannedQty, approvedQty, unitPrice?, currencyCode? — all strings)
- src/db/schema/boq-items.ts (numeric precision 12,3 qty; unit_price numeric 15,4)
- .planning/phases/07-data-foundation-canonical-record/07-RESEARCH.md (decimal.js is the display-layer money tool; money never multiplied as JS float)
</read_first>
