## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → RSC page | searchParams (project id) is caller-controlled |
| client dialog → Server Action | form input (create) / periodId (delete) crosses into financial mutations |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-03-EoP | Elevation of Privilege | list page RSC | mitigate | `auth()` redirect is the first statement; the (admin) layout also guards (defense in depth) |
| T-10-03-IDOR | Information Disclosure | ?project= param → getPeriodsByProject | mitigate | getPeriodsByProject (Wave 2) is tenant-scoped — a guessed project id from another tenant returns no rows |
| T-10-03-IV | Tampering | rate % inputs in the dialog | mitigate | createPeriod (Wave 2) zod-validates rate fractions server-side; the client % conversion is convenience only, never the trust boundary |
| T-10-03-DEL | Tampering | Sil affordance → deletePeriod on a non-draft period | mitigate | the UI gates the Sil affordance to `status === 'draft'` rows (controls absent, not disabled — D-96/D-97); deletePeriod (Wave 2) ALSO throws 'Cannot delete a finalized period' server-side (defense in depth) |
| T-10-03-XSS | Information Disclosure | period label / project name render | mitigate | React auto-escapes all interpolated values; no dangerouslySetInnerHTML |
| T-10-03-SC | Tampering | npm installs | accept | no new npm packages (Switch added in Wave 1 from official registry) |
</threat_model>
