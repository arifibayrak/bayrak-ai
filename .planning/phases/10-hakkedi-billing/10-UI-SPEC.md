## Spacing Scale

Unchanged from project baseline (8-point scale). Phase 10 uses identical spacing
to Phases 8–9 — replicate `space-y-6` / `gap-4` / `px-4 pb-4` patterns from
`KpiCard`, `SettingsPage`, and `OverviewPage`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (`gap-1`), inline label–input spacing |
| sm | 8px | Compact row padding, badge gap (`gap-2`) |
| compact | 12px | Deduction summary table rows (`py-3`) + finalized immutability banner (`p-3`) — declared exception for 7-row chain scannability |
| md | 16px | Default element spacing (`gap-4`, `px-4`) |
| lg | 24px | Section padding (`space-y-6`), card internal padding (`pb-4`) |
| xl | 32px | Between page sections (`space-y-8`) |
| 2xl | 48px | Major section breaks (used sparingly) |
| 3xl | 64px | Not used in this phase |

`compact` (12px) is a declared token — it is NOT an undeclared exception.
Usage is restricted to: deduction summary chain rows (`py-3`) and the
finalized immutability banner (`p-3`). No other surfaces may use 12px.

## Typography

Matches existing admin pages exactly. All heading sizing is from globals.css
`h1..h4` + `letter-spacing: -0.02em`.

**Weight-not-size rule:** The section heading (16px, semibold) vs. body/cell
text (14px, regular) differentiation is intentionally by SIZE (16 vs 14px) AND
WEIGHT (semibold vs regular). Do NOT add an intermediate size between 14px and
16px — there are exactly 4 declared sizes, and the visual hierarchy is achieved
using those 4 sizes combined with 2 declared weights. The executor must not
introduce a 15px or other unlisted size.

| Role | Size | Weight | Line Height | Tailwind class |
|------|------|--------|-------------|----------------|
| Page heading | 20px (text-xl) | 600 (semibold) | 1.4 | `text-xl font-semibold` |
| Section heading | 16px (text-base) | 600 (semibold) | 1.4 | `text-base font-semibold` |
| Body / cell text | 14px (text-sm) | 400 (regular) | 1.5 | `text-sm` |
| Muted label / sub | 14px (text-sm) | 400 (regular) | 1.5 | `text-sm text-muted-foreground` |
| Money value (net ödeme) | 24px (text-2xl) | 600 (semibold) | 1.3 | `text-2xl font-semibold tabular-nums` |
| Money value (line items) | 14px (text-sm) | 400 (regular) | 1.5 | `text-sm tabular-nums` |

`tabular-nums` is mandatory on every monetary value (aligns decimal columns).
Inter's `"cv11"` and `"ss01"` features are already active via globals.css.

**RSC:** `force-dynamic`, async, `auth()` guard first

### Surface 2: Create Period Dialog (HAK-01)
**Trigger:** "Dönem Oluştur" CTA on list page
**Component:** shadcn `<Dialog>` (already installed)
**Width:** `max-w-md` (448px) — matches settings dialog precedents

**Form fields** (top to bottom, each with `<label>` + `<Input>` or `<Select>`):

| Field | Type | Required | Default | Notes |

| Başlangıç Tarihi / Start Date | `<Input type="date">` | No | Empty | Informational; Istanbul tz hint text |
| Bitiş Tarihi / End Date | `<Input type="date">` | Yes | Today | The cumulative cutoff (D-100) |

| Avans Kesintisi Oranı | `<Input type="number">` | Yes | 0 | Displays as %; stored as 0.0000 |

**Rate inputs:** `w-[100px]` with a `%` suffix span to the right, displayed via

**Stopaj toggle layout:**
```
<div className="flex items-center justify-between">
  <label className="text-sm font-semibold">{t('hakedis.form.stopaj_label')}</label>
  <Switch checked={stopajEnabled} onCheckedChange={...} />

**Note on Switch:** `<Switch>` is NOT in the installed shadcn set. Use

**Form layout:** `<div className="space-y-4">` between fields. Section divider
(`<Separator />`) between date fields and rate fields with a label:
"Kesinti Oranları / Deduction Rates".

**Dialog footer:** Two buttons:
- "Vazgeç / Discard" — `variant="ghost"` — closes dialog, discards all form input, no mutation
- "Oluştur ve Hesapla / Create & Compute" — `variant="default"` (primary) — submits

  D-98), then navigates to the new period's detail page

**Error state (inline, below footer):**
```

## State Machine: Interaction Flow

```
[List Page]
  │
  ├─► [Create Dialog] ──► createPeriod() ──► [Detail Page: draft]
  │
  └─► [Detail Page: draft]
        ├─► Yeniden Hesapla ──► recomputePeriod() ──► (same page, lines refreshed)
        ├─► Kesinleştir ──► [Finalize Confirm Dialog] ──► finalizePeriod() ──► (same page: finalized)
        └─► Sil ──► [Delete Confirm Dialog] ──► deletePeriod() ──► [List Page]

      [Detail Page: finalized]
        └─► Tahakkuk Et ──► advanceStatus('submitted') ──► (same page: submitted)

      [Detail Page: submitted]
        └─► Ödendi ──► advanceStatus('paid') ──► (same page: paid)
```

**After finalizePeriod():** page re-renders with finalized banner, no
recompute/edit/delete controls. Status badge updates to `finalized`.

**After advanceStatus():** page re-renders with updated badge and next available
control (or none when `paid`).

**Error handling for blocked recompute (finalized):** server action returns error;
show `<Alert variant="destructive">` inline at top of detail page. Button is
absent from the UI by state-gate, so this is a defense-in-depth guard only.

## Money Display Rules

1. All monetary computation happens in Postgres (`numeric` type). No JS float
   arithmetic for money.
2. Values arrive in the page as `string` (returned from analytics/hakedis
   actions as strings, matching existing analytics.ts pattern).
3. Display via `new Decimal(value).toFixed(2)` (decimal.js). Never
   `parseFloat().toFixed(2)`.
4. TR locale formatting: `toLocaleString('tr-TR')` → periods as thousands
   separators, comma as decimal separator (e.g. "12.450,00").
5. EN locale formatting: `toLocaleString('en-US')` → commas as thousands
   separators, period as decimal separator (e.g. "12,450.00").
6. Currency displayed as ISO code suffix (TRY, USD, EUR) — not symbol — for
   multi-currency clarity. Exception: TRY may use ₺ prefix on TR locale.
7. "—" (em dash) shown when a money value is null/not-yet-computed (draft with
   no lines).
8. `tabular-nums` class mandatory on every money column cell.
