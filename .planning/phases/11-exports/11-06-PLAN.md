## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → period detail page | requires session — page-level auth already enforced by Phase 10 |
| anchor href → /api/exports/hakedis/[periodId] | route handler enforces auth + tenant scope + draft guard independently (Plan 11-04) |
| OE scorecard action_type → t() | action_type from DB feeds into translation key lookup |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-06-AUTH | Spoofing | new download anchors | mitigate | The route handlers behind the anchors are independently auth-guarded per D-114 (Plan 11-04). Even if the client renders the button somehow without session, the server returns 401. |
| T-11-06-DRAFT | Tampering | client-side draft hide | mitigate | Buttons removed (not disabled) when `status === 'draft'` — UI-SPEC + D-96. Server-side enforcement is in Plan 11-04 (Pitfall 5). Defense in depth. |
| T-11-06-IDOR | Information Disclosure | periodId in href | accept | The periodId is server-rendered into the page from a tenant-scoped query (Plan 10 page logic). A malicious user editing the periodId in the URL would hit Plan 11-04's tenant-scoped 404. |
| T-11-06-XSS | Tampering | aria-label from t() | mitigate | t() returns trusted translation strings from compiled message files; React JSX auto-escapes. No `dangerouslySetInnerHTML`. |
| T-11-06-MAP-OVERWRITE | Tampering | actionTypeToKey() unknown action_type | accept | Function falls through to `'action_unknown'` for any unmapped string. The DB write side is constrained by the TypeScript `OfficeActionType` union (Plan 11-01a) — only the 20 known strings can ever be inserted by app code. Unknown values can only enter via direct SQL, which is out of scope. |
</threat_model>
