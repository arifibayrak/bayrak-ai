**Amber for "In Progress" resolution (15-CONTEXT.md D-04 note):**
The D-04 decision uses amber for "in-progress" status, which overlaps with the brand CTA colour. Resolution:
- In-progress status badge uses `BrandBadge variant="primary"` (amber-50 bg / amber-700 text) — this is a **status pill**, not a button. The read-as-information vs read-as-action distinction is achieved through shape: pills are `rounded-full`, buttons are `rounded-md`.
- The chainage bar in-progress segment uses `bg-amber-300` (lighter than amber-500) to visually separate it from active-CTA amber. This creates sufficient contrast hierarchy: amber-500 = CTA / amber-300 = status.
- Exact colour bar segment classes: `bg-emerald-400` (approved), `bg-amber-300` (in-progress), `bg-slate-200` (not-started).

**Accent reserved for:** Granularity toggle active tab indicator, export button primary fill (Excel/PDF triggers), calibration save button, chainage bar in-progress segments (as amber-300, not amber-500).

**Chainage formatting function** (shared utility, not a copy decision):
```ts
// formatChainage(metres: number): string
// 2347 → "km 2+347"   |   12480 → "km 12+480"   |   500 → "km 0+500"
export function formatChainage(m: number): string {
  const km = Math.floor(m / 1000);
  const remainder = Math.round(m % 1000).toString().padStart(3, '0');
  return `km ${km}+${remainder}`;
}
```
This is a display utility, not i18n — the "km X+YYY" format is identical in TR and EN for this domain.

## Interaction Contracts

### Granularity Toggle
- Default: 1000 m (1 km) on tab open.
- Switching granularity immediately re-queries `getChainageBuckets(projectId, newBucketSizeM)` via client-side Server Action call inside `useTransition`.
- Loading state: show a `LoadingSpinner` (existing pattern) overlay on the table only — the colour bar and KPI row remain visible during the refetch.
- The selected granularity is NOT persisted to URL or localStorage in Phase 15 (simplicity — default on re-open).

### Chainage Colour Bar
- Not interactive (no click, no hover tooltip) — declarative status summary only.
- Colour bar updates when granularity changes (same data, different segment widths).

### Table Row Drill-Down (CHN-05)
- Clicking "Detay →" navigates to `/dashboard/records/[submissionId]?from=asbuilt`.
- The `SubmissionDetailView` renders a back-link when `from=asbuilt` query param is present: "← As-Built'e dön" / "← Back to As-Built" navigating `router.back()`.
- The back-link uses `BrandButton variant="ghost" size="sm"` with `ChevronLeft` icon size-4.

### Calibration Offset Save
- Optimistic: disable the save button immediately on click.
- On success: `router.refresh()` re-fetches the RSC. The colour bar and table re-render with calibrated chainages. Toast: "Kaydedildi".
- On error: re-enable button, show inline error below input in `text-xs text-destructive`.
- No confirmation dialog (change is reversible, not destructive).

### Export Downloads
- Click opens `/api/exports/chainage?...` in a new tab (`window.open(..., '_blank')`).
- No confirmation dialog.
- Auth 401 handled server-side (redirects browser to `/auth/signin` via the route handler's JSON 401 — same pattern as Phase 11 exports; client does not intercept).

## Phase-Specific Implementation Notes

These are binding visual/interaction constraints the executor must follow, not suggestions.

1. **No charting library** (D-03, Claude's Discretion): The chainage colour bar is 100% CSS flex with no import of recharts, d3, visx, or any other charting library. Violating this adds ~60 KB to the bundle unnecessarily.

2. **Chainage format is always "km X+YYY"** (CONTEXT.md): Every surface that displays chainage — strip table, Telegram notification, Excel export, PDF export — uses `formatChainage()` from a shared utility module. No ad-hoc formatting inline. The calibrated value (after offset) is what is displayed; the raw value is never shown to users.

3. **BrandBadge for all status pills** (BRAND.md D-125): Status in the table uses `BrandBadge`. Do NOT use raw Tailwind classes with ad-hoc colours for status pills. Variant mapping: approved=`"success"`, in-progress=`"primary"`, not-started=`"neutral"`.

4. **In-progress amber is amber-300 in the bar, amber-50/amber-700 in badges** (colour reconciliation above): The colour bar segment and the status pill are different surfaces with different contrast requirements. Apply them separately.

5. **Existing KpiCard unchanged** (Phase 13 contract): The KpiCard component is NOT modified in Phase 15. It is used as-is with the props defined in the Surface Specifications above.

6. **Tab added via existing Tabs pattern** (project page): Add `tab=asbuilt` to the URL search param guard in `ProjectDetailPage`. Add `TabsTrigger value="asbuilt"` and `TabsContent value="asbuilt"` in the same pattern as the existing four tabs. Do not restructure the tab bar.

7. **BrandEmpty for zero-state** (BRAND.md D-125): When `ChainageBucket[]` is empty (no approved submissions on this project), render `BrandEmpty` with `MapPin` icon, the empty state heading and body from the copywriting contract above. No raw empty-state patterns.

8. **force-dynamic on ChainageTab** (v2.0 rule): `export const dynamic = 'force-dynamic'`. Chainage data reflects live approval state; it must never be statically cached.

9. **Back-link on SubmissionDetailView** (CHN-05): The back-link only renders when `searchParams.from === 'asbuilt'`. It uses `router.back()` (not a hardcoded href) so it always returns to the originating strip, regardless of project ID.

10. **PDF aesthetic parity** (SC-6): The chainage PDF uses the same `@react-pdf/renderer` + DejaVu Sans font setup as the Phase 11 hakkediş certificate. Same header style, same table cell padding, same footer. Executor must read `src/lib/pdf/hakedis-pdf.tsx` before authoring `src/lib/pdf/chainage-pdf.tsx`.
