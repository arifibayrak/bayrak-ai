<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram callback_data → step handler | worker-controlled IDs must be re-validated against the DB, not trusted |
| Telegram free-text notes → DB | untrusted free text crosses into a stored column |
| Telegram message type → FSM advance | only the expected message type may advance a step |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Tampering | callback_data selecting an unassigned project/BOQ item | mitigate | Project + BOQ handlers re-query the worker's assignments / project boqItems and reject any id not owned by the worker (Task 1, V4) — the callback id is never trusted |
| T-02-13 | Tampering | input-type confusion (text where photo/location expected) advancing the FSM | mitigate | Each step strictly checks message type (photo / native location / numeric) and reprompts without advancing on mismatch (Tasks 2-3, D-19/D-20, LOG-09) |
| T-02-14 | Injection | malicious free-text in notes | mitigate | Notes stored via parameterized Drizzle insert (no string-built SQL) + defensive length cap (~1000 chars) at the notes step (Task 3, V5) |
| T-02-12 | Availability | unanswered callback_query (page/select/skip) | mitigate | every callback handler calls ctx.answerCallbackQuery() first (Pitfall 3) |
| T-02-15 | Availability | photo upload failure crashing the step | mitigate | photo handler wraps uploadPhotoToBlob in try/catch, replies a Turkish error, and stays on the step rather than throwing (Task 2) |
| T-02-SC | Tampering | npm installs | accept | No installs this phase |
</threat_model>
