<objective>
Wire the bot pipeline scaffold into the existing `src/lib/telegram.ts`: (1) the idempotency middleware that fences duplicate `update_id`s before any handler runs (D-13 Guard 1, LOG-10/SC4 plumbing); (2) the worker identity guard that resolves `ctx.from.id` → active person + assigned projects and rejects unregistered users (LOG-01); (3) the `/start` handler that greets a registered worker by name and shows their projects, or offers Devam/Baştan when a flow is in progress (D-15); (4) `/iptal` cancel at any step (D-17); and (5) the FSM dispatcher `bot.on('message'|'callback_query')` that loads `conversation_state`, applies the TTL check (D-22), and reprompts the current step on cold-start resume (D-14, SC5). Step BODIES (project→notes) are Plan 05; this plan establishes the dispatch frame and resume behavior.

Purpose: This is the control spine of the worker bot. Interface-first: it defines how every step handler is invoked and how state is loaded/saved, so Plan 05 just fills step bodies.
Output: Extended telegram.ts + unit tests for dedup, identity, /start greeting, resume, and TTL.
</objective>

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02 | Tampering / Spoofing | duplicate/replayed update_id | mitigate | Idempotency middleware (D-13 Guard 1) is the FIRST middleware: INSERT processed_updates ON CONFLICT DO NOTHING; replay returns empty → handlers skipped (Task 1) |
| T-02-09 | Elevation of privilege | unregistered user driving the FSM | mitigate | resolveWorker returns null for non-active identities → pendingApproval reply, FSM not entered (Task 1/2, LOG-01) |

| T-02-11 | Information disclosure | stale flow leaking a day-old partial submission to a new task | mitigate | isStaleState TTL check (D-22) treats >24h rows as abandoned; the worker starts clean |
| T-02-12 | Availability | callback_query left unanswered → Telegram spinner + retry storm | mitigate | every callback handler calls ctx.answerCallbackQuery() first (Pitfall 3) |
| T-02-SC | Tampering | npm installs | accept | No installs — grammy, drizzle, neon already audited in Phase 1 |
