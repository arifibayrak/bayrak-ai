## Spacing Scale

Declared values (all multiples of 4, following Tailwind 4 / 8-point grid):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, tight inline padding |
| sm | 8px | Compact element spacing, badge padding |
| md | 16px | Default element spacing, card internal padding |
| lg | 24px | Section padding, card-to-card gap |
| xl | 32px | Tab panel top padding, major layout gaps |
| 2xl | 48px | Page-level section breaks |
| 3xl | 64px | Reserved for future top-level layout only |

Exceptions:

- Map height on desktop: `h-[600px]`; on mobile: `h-[400px]` — not a spacing token but a layout constraint
- Touch targets (filter chips, tab triggers, map popup close button): minimum 44px height on mobile (WCAG 2.5.5 practical target, D-59)
- Mapbox marker click area: 32px × 32px minimum

## Typography

All sizes use Geist Sans (`--font-sans`). Tailwind v4 utility classes map directly.

| Role | Size | Weight | Line Height | Tailwind class |
|------|------|--------|-------------|----------------|
| Body | 14px | 400 (regular) | 1.5 | `text-sm` |
| Label | 14px | 600 (semibold) | 1.4 | `text-sm font-semibold` |
| Heading | 16px | 600 (semibold) | 1.4 | `text-base font-semibold` |
| Display | 20px | 600 (semibold) | 1.2 | `text-xl font-semibold` |

Rules:
- **Only 2 font weights in use:** 400 (regular) and 600 (semibold). No 500, no 700.
- Numbers in tables (quantities, distances, percentages): `tabular-nums` class — established pattern from BoqTable.tsx.
- Locale formatting: `Intl.NumberFormat('tr-TR')` for quantities; `toLocaleDateString('tr-TR')` for dates — established pattern.
- Map popup labels: Body (14px/400). Popup heading (BOQ item name): Label (14px/600).

## Color

The project uses shadcn `neutral` tokens via OKLCH CSS variables. No raw hex is hardcoded for UI chrome — only BOQ palette markers use fixed hex.

| Role | Token / Value | Usage |
|------|---------------|-------|
| Dominant (60%) | `--background` (`oklch(1 0 0)` light / `oklch(0.145 0 0)` dark) | Page backgrounds, table rows |
| Secondary (30%) | `--card` / `--muted` (`oklch(0.97 0 0)` light) | Cards, sidebar, tab panels, map popup background |
| Accent (10%) | `--primary` (`oklch(0.205 0 0)` light) | See reserved list below |
| Destructive | `--destructive` (`oklch(0.577 0.245 27.325)`) | Rejected status badge, BOQ depleted row indicator, delete actions only |
| Success | `hsl(142 76% 36%)` | BOQ balance > 10% — established BoqTable.tsx pattern |
| Warning | `hsl(38 92% 50%)` | BOQ balance ≤ 10%, location anomaly ring — established BoqTable.tsx pattern |

**Accent reserved for (explicit list):**
1. Active tab underline / selected tab trigger
2. Primary CTA buttons (e.g. "Rota Yükle")
3. Filter chip active/selected state border
4. Progress bar fill (BOQ completion percentage)
5. Focus ring (`--ring`)

**Accent is NOT used for:** table row hover, map popups, status badges, icons in passive state.

### BOQ Item Color Palette (map markers — D-58)

Color-blind-safe palette assigned to BOQ items in stable creation-order. These are the only hardcoded hex values in the system.

| Slot | Hex | Approx. color | Color-blind safe? |
|------|-----|---------------|-------------------|
| 1 | `#2563EB` | Blue | Yes (distinguishable in deuteranopia) |
| 2 | `#D97706` | Amber | Yes |
| 3 | `#7C3AED` | Violet | Yes |
| 4 | `#059669` | Emerald | Yes (avoid adjacent to slot 1 in tritanopia — use shape cue) |
| 5 | `#DB2777` | Pink/Rose | Yes |
| 6 | `#0891B2` | Cyan | Yes |

Overflow rule (> 6 BOQ items): cycle palette AND append a numbered superscript label (1–N) to the marker so items remain distinguishable without relying on hue alone (D-58).

**Anomaly overlay (D-52):** A 3px warning-ring in `hsl(38 92% 50%)` (amber) is layered OUTSIDE the BOQ-item colored circle for `location_match='far'` markers. Shape + color dual cue — not hue alone (D-59).

**Route line color:** `#64748B` (slate-500) at 3px width, 80% opacity. Chosen to read on Mapbox Outdoors/Streets base map without competing with BOQ marker palette. Claude's discretion per D-52.

## Layout & Interaction Patterns

### Tab shell (D-49)

Tab order (TR labels): **BOQ · Rota · Kayıtlar · Personel**

- URL state: `?tab=boq | rota | kayitlar | personel` — existing pattern from Phase 1
- Pattern: `XTab` (server-fetch) + `XTabClient` (interactivity)
- Tab trigger min-height: 44px on mobile

### Rota tab — Mapbox map (DASH-01, DASH-02, D-49, D-51, D-56)

Layout (desktop): full-width map at `h-[600px]`, upload control below the map as a collapsible secondary action.

Layout (mobile): map at `h-[400px]`, upload control below in full-width card.

Map layers (react-map-gl `<Source>` / `<Layer>` approach — Claude's discretion per context):
1. **Route line layer** — GeoJSON LineString from `routes.geom` (`ST_AsGeoJSON`), rendered as a `line` layer, color `#64748B`, width 3px.
2. **Approved points layer** — GeoJSON FeatureCollection of approved submissions with `snapped_point IS NOT NULL`, rendered as `circle` layer, color from BOQ palette.
3. **Anomaly ring layer** — second `circle` layer for `location_warning=true` points, rendered as larger circle with stroke in `hsl(38 92% 50%)` and transparent fill.

Map viewport: `fitBounds` to route bounding box on load (D-56, padding 48px all sides).

Interactivity:
- Clicking a point opens a Mapbox popup (D-51). No click on line layer.
- Keyboard pan/zoom via Mapbox GL built-in (D-59).
- `router.refresh()` on `visibilitychange` / window `focus` (D-55).

**Popup content (D-51):**
- Photo thumbnail: `next/image` 80×80px, `object-cover`, lazy loaded
- BOQ item name (Label size)
- Quantity + unit (Body)
- Status badge (see status badge spec below)
- Date decided (Body, `toLocaleDateString('tr-TR')`)
- Deciding auditor name (Body, muted)
- If `location_warning=true`: distance in metres, warning amber text

**Map legend:** Positioned bottom-left, overlaid on map. Lists BOQ item name → colored swatch. Rendered as a Card with `bg-background/90` backdrop. Hidden if no approved points exist.

### BOQ tab — progress columns (DASH-04, D-50)

Extend existing `BoqTable` with two new columns inserted after `Approved Qty`:

| New column | Content |
|------------|---------|
| `% Tamamlanan` | `(approvedQty / plannedQty * 100)` formatted as `Intl.NumberFormat('tr-TR', {maximumFractionDigits:1})` + `%` |
| Progress bar | shadcn `<Progress>` component, value 0–100, width `min-w-[80px]`, height `h-2` |

Progress bar fill: accent color (`--primary`) for 0–89%, success green for 90–100%, warning amber at ≤10% completion when balance is nearly depleted. Use same `balanceColorClass` logic extended for progress direction.

Zero-progress row: `<Progress value={0} />` renders empty bar — no special state needed.

### Kayıtlar tab — submissions list (DASH-03, D-53, D-54)

Table columns (in order):

| Column | Content | Width |
|--------|---------|-------|
| Fotoğraf | `next/image` 48×48px thumbnail → Dialog lightbox on click | `w-16` |
| BOQ Kalemi | `boq_item.material` | `min-w-[150px]` |
| Miktar | quantity + unit, `tabular-nums` | `w-24 text-right` |
| Durum | Status badge (see below) | `w-28` |
| Tarih | `decided_at` or `created_at`, `toLocaleDateString('tr-TR')` | `w-28` |
| Konum | Google Maps link (Phase 3 pattern: `maps.google.com/?q=<lat>,<lon>`) with ExternalLink icon | `w-24` |
| Notlar | truncated to 60 chars, full text in tooltip | `min-w-[120px]` |

Filter chips (above table, D-54): **Tümü · Bekliyor · Onaylandı · Reddedildi**

- Chip style: outline variant buttons with active state using `border-primary text-primary`
- Default selected: "Tümü"

Pagination: page size 25, previous/next buttons. Simplest approach — no infinite scroll. Page number shown as "Sayfa N / M".

Sort: newest-first (`created_at DESC` default, not user-configurable in v1).

Mobile: table horizontally scrollable (`overflow-x-auto` wrapper).

**Status badge spec:**

| Status | Variant | Copy (TR) | Copy (EN) |
|--------|---------|-----------|-----------|
| `pending_audit` | `secondary` (muted) | Beklemede | Pending |
| `approved` | custom `bg-emerald-100 text-emerald-800` | Onaylandı | Approved |
| `rejected` | `destructive` | Reddedildi | Rejected |

Status badge uses `<Badge>` component. Approved uses inline className override to stay within the 2-color-weight palette while remaining visually distinct from accent.

### Photo lightbox (D-61)

Trigger: clicking any photo thumbnail in Kayıtlar table or map popup.

Component: shadcn `<Dialog>` with `max-w-3xl`. Inner content: `next/image` with `width={800} height={600} objectFit="contain"`.

**next.config change required:** Add Vercel Blob hostname to `images.remotePatterns` before Phase 5 can render photos (D-61 — flag for planning as explicit task).

## Accessibility Checklist (D-59 practical scope)

- Color is never the only signal: status badges carry text; map anomaly uses shape (ring) + text in popup; BOQ progress uses numeric % + color bar.
- Map legend maps color → material name text.
- BOQ overflow beyond 6 items: numbered superscript on markers as secondary cue.
- Keyboard: Mapbox GL JS provides built-in pan/zoom (`+`/`-`, arrow keys).
- Touch targets: filter chips and tab triggers minimum 44px height on mobile.
- `next/image` must include descriptive `alt` text: photo thumbnails use `"[BOQ item] fotoğrafı"` pattern.
- All new next-intl message keys follow existing namespace pattern (`dashboard.*`).

## Liveness / Refresh (D-55)

- All data-fetching Server Components: `export const dynamic = 'force-dynamic'` (no caching)
- Client-side refresh: `useEffect` listening to `document.addEventListener('visibilitychange', ...)` and `window.addEventListener('focus', ...)` → calls `router.refresh()` when tab becomes visible
- Location: one `useRouterRefresh` hook in the project-detail page Client wrapper, applies to all tabs
