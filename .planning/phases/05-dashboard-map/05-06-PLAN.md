<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL searchParams (tab/status/page) → page → KayitlarTab | user-controlled routing params reach the server fetch |
| client focus events → router.refresh → server re-fetch | refresh re-runs the auth+tenant-scoped fetch each time |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-IV | Tampering | status/page searchParams | mitigate | KayitlarTab (Plan 04) falls back to 'all' on invalid status and coerces page to a positive int; getSubmissions (Plan 02) whitelists status |
| T-05-AC | Information Disclosure | force-dynamic page + refresh | accept | The page route is already auth-guarded (dashboard guard, Phase 1); force-dynamic only disables caching, it does not relax authz; every fetch re-runs the auth+tenant scope |
| T-05-DOS | Denial of Service | router.refresh on focus | accept | Refresh fires only on focus/visibility regain (not a polling loop); refresh latency is bounded by the lightweight server fetch — acceptable for a single-tenant office dashboard (real-time/WebSocket explicitly out of scope) |
</threat_model>
