<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| application code → database | All writes must scope tenant_id to the seed tenant; geometry inserts must be parameterized |
| migration tooling → live DB | A wrong geometry type silently corrupts all downstream spatial work |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | routes.geom column type | mitigate | Hand-edit point→LineString with regression-guard comment; grep gate fails build if `geometry(point` remains; never use `drizzle-kit push` directly |
| T-02-02 | Information Disclosure | cross-tenant leakage (D-09 hedge) | mitigate | `getDefaultTenantId()` helper; app code always supplies tenant_id on insert (Pitfall 3); seed tenant isolated by fixed UUID |
| T-02-03 | Denial of Service | missing GiST index on geom | accept | Single-tenant low-row-count in v1; GiST index is added now so Phase 4 spatial queries are index-backed — accepted as mitigated-forward |
| T-02-04 | Tampering | GeoJSON geometry injection at insert | mitigate | Geometry inserted only via parameterized `ST_GeomFromGeoJSON(${...})` (validated upstream in plan 01-06); no string concatenation into SQL |
</threat_model>
