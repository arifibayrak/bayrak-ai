# Phase 1 — UI Design Contract: Foundation

> Visual and interaction contract for the bayrak.ai office dashboard foundation.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> Scope: magic-link sign-in · project list · project detail (BOQ + GeoJSON route + People/Pending-approval queue) · TR/EN language toggle.
> Out of scope: Mapbox map (Phase 5) · AI badges (Phase 6) · Telegram bot UI (Phases 2–3).

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn/ui |
| Preset | none (default neutral — run `npx shadcn@latest init` during Phase 1 setup with style: default, base color: neutral, CSS variables: yes) |
| Component library | Radix UI (via shadcn/ui) |
| Icon library | lucide-react (bundled with shadcn/ui) |
| Font | Geist Sans (Next.js default via `next/font/google`; fallback: system-ui) |

**shadcn initialization command:**
```bash
npx shadcn@latest init --defaults
```
Choose: style=default, base color=neutral, CSS variables=yes. This produces `components.json` and configures Tailwind CSS v4 with shadcn's CSS variable layer.

**Rationale for neutral palette:** This is an internal B2B operational tool used by an office engineer, not a marketing surface. Neutral grey base maximizes readability of dense tabular data (BOQ line items, people lists) without distracting color.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge internal padding |
| sm | 8px | Compact table cell padding, inline chip spacing |
| md | 16px | Default element spacing, form field gaps, button padding |
| lg | 24px | Card internal padding, section header bottom margin |
| xl | 32px | Layout column gap, page section separation |
| 2xl | 48px | Major section breaks (between BOQ / Route / People sections on project detail) |
| 3xl | 64px | Page-level vertical padding on sign-in screen |

Exceptions:
- Touch/click targets on table row actions: minimum 44px height (accessibility, fat-finger safety on dense data tables)
- Language toggle pill: 36px height (compact placement in top nav, not a primary action)

## Typography

Four sizes, two weights only. Optimized for data density and Turkish string length (Turkish labels run ~20-30% longer than English equivalents; use 14px minimum for labels with adequate width).

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 14px | 400 (Regular) | 1.5 | Table cell content, form helper text, metadata, form labels, table column headers, button text |
| Heading | 20px | 600 (Semibold) | 1.3 | Page title, section headings (BOQ, Rota, Personel) |
| Display | 28px | 600 (Semibold) | 1.2 | Sign-in page welcome copy only |

**Weight rule:** Exactly two weights — 400 (Regular) for all body-level text, 600 (Semibold) for all headings and display. The former Medium (500) weight is not used; shadcn button text and form labels render at 400.

**Number formatting (Turkish locale):**
- Use `Intl.NumberFormat('tr-TR')` for quantities and balances displayed in Turkish mode
- Decimal separator: comma (`,`) in Turkish; period (`.`) in English
- Example: `1.234,56` (TR) vs `1,234.56` (EN)
- Always format BOQ quantities and remaining balances with locale-aware formatter, never hard-code separators

**Turkish string accommodation:**
- Table column widths must not clip Turkish labels; use `min-w-[120px]` for material/unit columns
- Allow word-wrap for material description cells; do not truncate with ellipsis unless cell width < 80px

## Color

shadcn/ui neutral CSS-variable palette. All color references use CSS variables, never hard-coded hex in component code.

| Role | CSS Variable | Tailwind Class | Usage |
|------|-------------|----------------|-------|
| Dominant (60%) | `--background` | `bg-background` | Page background, main content area |
| Secondary (30%) | `--card` / `--muted` | `bg-card` / `bg-muted` | Cards, sidebar nav, table zebra rows, section containers |

| Warning | `--` (custom: `hsl(38 92% 50%)`) | Use inline `text-[hsl(38_92%_50%)]` | Pending people queue count badge; BOQ remaining balance approaching zero (< 10% remaining) |

**Accent reserved for (explicit list):**

2. Active nav/tab indicator (left border or underline on the active project section tab)
3. File upload drop zone border-color on hover/drag-over state
4. "Personeli Onayla / Approve Person" button in the pending people queue (promotes a worker/auditor to active)

**Destructive reserved for:**
1. "Projeyi Sil / Delete Project" — confirmation dialog required (see Copywriting)
2. "BOQ Kalemini Kaldır / Remove BOQ Item" — confirmation required
3. "Görevi Kaldır / Remove Assignment" — confirmation required

## Screen Inventory and Interaction Contracts

### 1. Sign-In Screen (`/auth/signin`)

**Focal point:** The email input and "Giriş Bağlantısı Gönder / Send Sign-In Link" CTA button — vertically centered, full-width within the card.

**Layout:** Centered card on full-height background. Single column. No sidebar.

**Elements:**
- Display-size heading: "bayrak.ai" (28px/semibold)
- Sub-heading (heading size): "Ofis Girişi / Office Sign-In" — language-switchable
- Email input field with label "E-posta / Email"
- Primary CTA button: "Giriş Bağlantısı Gönder / Send Sign-In Link" — full width
- Helper text (body/regular): "Yetkili e-posta adresinize giriş bağlantısı gönderilecek. / A sign-in link will be sent to your authorized email."
- Error state: shadcn `Alert` (destructive variant) — shown if email is not on the allowlist

**States:**
- Default: email input empty, button enabled
- Loading: button shows spinner + "Gönderiliyor... / Sending..." text, input disabled
- Success: card replaced with confirmation message (body copy, see Copywriting)
- Error (non-allowlisted): Alert appears below input; input remains editable

**Interaction:**
- Submit on Enter key in email field
- No auto-redirect; user clicks the link in email
- After clicking magic link: redirect to `/dashboard/projects`

---

### 2. Project List (`/dashboard/projects`)

**Focal point:** The "Proje Oluştur / Create Project" CTA at top-right and the project card list below the page heading.

**Layout:** Top nav + main content area. Responsive single-column list on narrow viewports.

**Top nav elements:**
- Left: "bayrak.ai" wordmark (heading size, semibold)
- Right: Language toggle (TR | EN pill — see Language Toggle below) + user email + sign-out button (ghost variant)

**Main content:**
- Page heading: "Projeler / Projects" (heading, semibold)
- Primary CTA: "Proje Oluştur / Create Project" button (top-right, primary variant)
- Project cards in vertical list: each card shows project name (body/regular, bold via semibold weight), creation date (body/regular), BOQ item count, People count
- Each card has a row action dropdown: "Düzenle / Edit" + "Sil / Delete" (destructive, with confirmation dialog)
- Empty state: see Copywriting

**States:**
- Loading: 3 skeleton cards
- Empty: empty state illustration (use lucide `FolderOpen` icon at 48px) + copy
- Populated: card list
- Error: Alert (destructive) with retry link

---

### 3. Project Create/Edit Form (`/dashboard/projects/new` and `/dashboard/projects/[id]/edit`)

**Focal point:** The Project Name field (auto-focused on mount) and the primary CTA button at the bottom of the form.

**Layout:** Full-page form, no sidebar. Back link to project list.

**Fields:**
- Project Name (required): text input, label "Proje Adı / Project Name"
- Description (optional): textarea, label "Açıklama / Description", max 500 chars, char count shown
- Primary CTA: "Proje Oluştur / Create Project" (on new) or "Değişiklikleri Kaydet / Save Changes" (on edit)
- Secondary: "Projeye Dön / Back to Project" (ghost button, navigates back — on edit) or "Projelere Dön / Back to Projects" (ghost button — on new)

**Validation:**
- Project name required: inline error below field "Proje adı zorunludur. / Project name is required."
- Show errors on submit attempt, not on blur (reduces friction for Turkish-language input with IME)

---

### 4. Project Detail (`/dashboard/projects/[id]`)

**Focal point:** The tab strip (BOQ / Route / Personel) and the active section's primary table or CTA. On initial load, the BOQ tab is active and the BOQ table with its "Kalem Ekle / Add Item" CTA is the focal point.

**Layout:** Top nav (same as project list) + page heading with project name + tab strip.

**Tab strip:** Three tabs using shadcn `Tabs` component:
- "Metraj (BOQ)" — tab 1, default active
- "Rota (GeoJSON)" — tab 2
- "Personel" — tab 3

Each tab is a full-width content panel below the tab strip with 48px top padding.

---

#### 4a. BOQ Tab

**Section heading:** "Metraj Kalemleri / Bill of Quantities" (heading/semibold) + two action buttons right-aligned:
- "Kalem Ekle / Add Item" (primary)
- "Excel'den İçe Aktar / Import from Excel" (outline variant)

**BOQ Table columns (in order):**
| Column | Width | Notes |
|--------|-------|-------|
| # | 40px | Row number |
| Malzeme / Material | min 200px | Text, wraps |
| Birim / Unit | 80px | e.g., m, m³, adet |
| Sözleşme Miktarı / Contracted Qty | 120px | Right-aligned, locale-formatted number |
| Onaylanan Miktar / Approved Qty | 120px | Right-aligned, starts at 0 (populated Phase 3+) |
| Kalan Bakiye / Remaining Balance | 120px | Right-aligned; color: success (> 10%), warning (≤ 10%), destructive (0 or negative) |
| İşlemler / Actions | 80px | Dropdown: Düzenle / Sil |

**Empty state (BOQ tab):** see Copywriting.

**Add/Edit BOQ Item:** inline row form OR a Dialog (use Dialog for first implementation). Fields: Material (text input, required), Unit (text input, required, e.g. "m", "m³", "adet"), Contracted Qty (number input, required, positive integer or decimal).

**Excel Import flow:**
1. User clicks "Excel'den İçe Aktar / Import from Excel"
2. Dialog opens: file input (.xlsx only, accept=".xlsx"), "Şablon İndir / Download Template" link (downloads a pre-populated .xlsx with correct column headers)
3. After file selection: show preview table (same columns as BOQ table, all rows from file, read-only) inside the dialog
4. Below preview: "X kalem içe aktarılacak / X items will be imported" count + "Onayla ve İçe Aktar / Confirm & Import" (primary) + "Projeye Dön / Back to Project" (ghost)
5. On confirm: close dialog, show toast success, BOQ table refreshes
6. On parse error: show Alert (destructive) inside dialog with row-level errors: "Satır 3: Miktar sayısal olmalı / Row 3: Quantity must be numeric"

---

#### 4b. Route (GeoJSON) Tab

**Focal point:** The upload drop zone (when no route exists) or the route metadata card with "Rotayı Değiştir / Replace Route" button (when a route is already saved).

**Section heading:** "Proje Rotası / Project Route" (heading/semibold)

**Upload area:**
- If no route uploaded: drag-and-drop zone (dotted border in `--primary` color on hover, neutral otherwise, `lg` border-radius, `2xl` height minimum 160px)
  - Icon: lucide `Upload` at 32px, centered
  - Label: "GeoJSON rotasını yükleyin / Upload GeoJSON route" (body/regular, centered)
  - Sub-label: ".geojson formatı · Tek LineString · WGS84 koordinatları" (body/regular, muted color, centered)
  - Hidden file input triggers on click or drag
- "Dosya Seç / Choose File" button (outline variant, below sub-label)

**Validation feedback (shown immediately after file selection, before save):**
- Loading state: spinner + "Doğrulanıyor... / Validating..." text replaces upload zone
- Success: green Alert with lucide `CheckCircle` icon — "Geçerli LineString rota. X koordinat noktası / Valid LineString route. X coordinate points." + "Rotayı Kaydet / Save Route" primary button
- Error states (each as a destructive Alert with specific copy — see Copywriting):
  - Not a GeoJSON file
  - Valid JSON but not a GeoJSON FeatureCollection or Feature
  - Correct GeoJSON but geometry type is not LineString (e.g., Polygon)
  - Coordinate order issue detected (lng not in -180–180 range)
- If a route is already saved: show current route metadata (file name if stored, coordinate count, upload date) + "Rotayı Değiştir / Replace Route" button (outline, destructive color — replacing deletes the old route)

#### 4c. People (Personel) Tab

**Focal point:** The "Bekleyen Onaylar / Pending Approvals" sub-section when pending count > 0 (requires immediate action); otherwise the "Aktif Personel / Active People" table and "Manuel Personel Ekle / Add Person Manually" CTA.

**Two sub-sections within the tab:**

**Sub-section 1: Bekleyen Onaylar / Pending Approvals**
- Shown only when `pending_people.length > 0`; otherwise hidden (not even a heading)
- Sub-heading: "Bekleyen Onaylar / Pending Approvals" (body/regular semibold via 600 weight, warning text color) + count badge (warning)
- Table columns:
  | Column | Notes |
  |--------|-------|
  | Telegram Adı / Telegram Name | From Telegram /start capture |
  | Telegram ID | Numeric, monospace font |
  | /start zamanı / Joined | Relative time (e.g., "2 saat önce / 2 hours ago") |
  | Ad / Name | Editable text input inline — office sets display name |
  | Rol / Role | Select: İşçi (Worker) / Denetçi (Auditor) |
  | Proje Ataması / Project | Select: list of active projects |
  | İşlemler / Actions | "Personeli Onayla / Approve Person" (primary, small) + "Personeli Reddet / Reject Person" (destructive, ghost, small) |
- "Personeli Onayla / Approve Person": validates Name and Role are filled; on success shows toast + row disappears
- "Personeli Reddet / Reject Person": no confirmation dialog required (pending person never had access); row disappears + toast

**Sub-section 2: Aktif Personel / Active People**
- Sub-heading: "Aktif Personel / Active People" (heading/semibold)
- CTA: "Manuel Personel Ekle / Add Person Manually" (outline variant, top-right) — for edge case where office registers a person without them using the bot first
- Table columns:
  | Column | Notes |
  |--------|-------|
  | Ad / Name | Display name |
  | Rol / Role | Badge: "İşçi" (muted) or "Denetçi" (secondary) |
  | Telegram ID | Numeric, monospace |
  | Proje / Project(s) | Comma-separated project names |
  | İşlemler / Actions | Dropdown: Düzenle / Görevi Kaldır (destructive) |
- Empty state: see Copywriting

**Manual Add Person form (Dialog):**
Fields: Display Name (text, required), Role (select: İşçi/Denetçi, required), Telegram User ID (number input, required, must be positive integer), Project Assignment (select, required).

### 5. Language Toggle

**Placement:** Top-right of nav bar, before user email.

**Appearance:** Inline pill with two segments — "TR" | "EN". Active segment: `bg-primary text-primary-foreground`. Inactive: `bg-muted text-muted-foreground`. Height: 36px. Width: auto (~72px total). Border-radius: full (pill shape).

**Behavior:**
- Toggle persists via `next-intl` locale cookie; survives page navigation and browser refresh
- Switching locale re-renders all i18n-keyed strings without a full page reload (next-intl client-side switching)
- All UI strings are i18n-keyed from the start; no hard-coded Turkish or English strings in component code
- Number formatting responds to locale: `tr-TR` in Turkish mode, `en-US` in English mode

**i18n key convention:** `namespace.component.key`, e.g., `dashboard.boq.add_item`, `auth.signin.cta`. All keys defined in `/messages/tr.json` (primary) and `/messages/en.json` (secondary).

## Interaction Patterns

### Form Validation Timing
- Show field-level errors on submit attempt, not on blur
- Exception: email field on sign-in page validates format on blur (prevents "not authorized" confusion)

### Feedback Toasts (shadcn sonner)
- Position: bottom-right
- Duration: 4 seconds for success, 8 seconds for errors (more time to read Turkish)
- Success variant: default (neutral)
- Error variant: destructive

### Loading States
- Table loading: skeleton rows matching expected row count (3 rows for initial load)
- Button loading: spinner replaces button icon (left position), text changes to in-progress copy, button disabled
- File validation: spinner replaces upload zone content with "Doğrulanıyor... / Validating..."

### Navigation
- Dashboard uses Next.js App Router file-based routing
- Tab state (BOQ/Route/Personel) persists in URL search param `?tab=boq|rota|personel` so direct links and browser back work
- Project detail breadcrumb: "Projeler / Projects > {projectName}" — each segment is a link

### Accessibility
- All interactive elements have visible focus rings (shadcn default ring style)
- Table headers have `scope="col"` attribute
- Form inputs have explicit `<label>` elements (never aria-label-only)
- Destructive dialog uses `role="alertdialog"` (shadcn Dialog default)
- Color is never the sole differentiator: BOQ remaining balance uses both color AND a numeric label
- Language toggle: `aria-label` = "Dil değiştir / Switch language", each segment has `aria-pressed`

## Layout Architecture

### Route Structure
```
/
├── /auth/signin          — sign-in page (no auth required)
├── /auth/verify          — magic-link verification landing (Auth.js default)
└── /dashboard/
    ├── layout.tsx        — top nav (lang toggle, user, sign-out) + Auth.js session guard
    ├── projects/
    │   ├── page.tsx      — project list
    │   ├── new/page.tsx  — create project form
    │   └── [id]/
    │       ├── page.tsx  — project detail (tabs)
    │       └── edit/page.tsx — edit project form
```

### Dashboard Layout
- Top nav: `h-14`, `bg-card`, `border-b border-border`, sticky
- Main content: `max-w-5xl mx-auto px-6 py-8` — centered, comfortable on 1280px+ monitors; full-width below 768px
- No persistent left sidebar in Phase 1 (project list is the nav; sidebar added in Phase 5 if needed)
- Tab strip: `border-b border-border` below page heading, `sticky top-14` so it stays visible while scrolling long BOQ tables

### Responsive behavior
- Primary use case: office desktop (1280px–1920px wide)
- Minimum supported: 768px (tablet — office use on a tablet is possible)
- Below 768px: tables scroll horizontally; forms stack single-column
- No mobile-first optimization required (field workers use Telegram bot, not the dashboard)
