<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser file upload → Server Action (GeoJSON / Excel) | Untrusted file content crosses here; must be validated/parsed safely before any DB write |
| parsed content → PostGIS / boq_items | Parsed values must be parameterized; no injection via file content |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering | GeoJSON injection via upload | mitigate | Server-side zod validation (validateLineStringGeoJSON) before any write; geometry inserted only via parameterized `ST_GeomFromGeoJSON(${...})` template literal (no string concat) |
| T-06-02 | Tampering | BOQ quantity/material injection via Excel | mitigate | parseFloat after comma→period normalization + positivity/range check; cell values read as typed strings, never eval()'d; inserted via Drizzle parameterized values |
| T-06-03 | Denial of Service | oversized upload (Excel/GeoJSON) | mitigate | .xlsx-only + .geojson-only accept filters; Next.js Server Action 4MB body limit enforced by framework; 4MB note surfaced in the UI sub-label |
| T-06-04 | Elevation of Privilege | unauthenticated BOQ/route/template actions | mitigate | uploadRoute, all BOQ actions, and the template download route call auth() and throw/deny when unauthenticated |
| T-06-05 | Spoofing | wrong-type file masquerading as .xlsx/.geojson | mitigate | previewBoqImport rejects non-.xlsx by extension and ExcelJS load failure; GeoJSON validator rejects non-LineString/non-GeoJSON with specific errors |
</threat_model>
