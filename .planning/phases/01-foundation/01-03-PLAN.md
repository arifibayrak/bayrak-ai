<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous browser → magic-link request | Untrusted email submitted; must be checked against allowlist before any email is sent |
| anonymous browser → /dashboard/* | Unauthenticated requests must be redirected, never served dashboard data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | magic-link sign-in (AUTH-01) | mitigate | signIn callback returns false for non-allowlisted emails on BOTH the verificationRequest and link-click calls — no email delivery, no session (D-11, Pitfall 2); unit-tested via isAllowed |
| T-03-02 | Elevation of Privilege | /dashboard/* access | mitigate | dashboard/layout.tsx calls `auth()` and redirects unauthenticated requests to /auth/signin before rendering |
| T-03-03 | Information Disclosure | allowlist via env | mitigate | AUTH_ALLOWED_EMAILS in env (gitignored .env.local); not exposed to client; error page reveals only generic "not authorized" copy, never the allowlist |
| T-03-04 | Spoofing | AUTH_SECRET strength | mitigate | AUTH_SECRET generated via `openssl rand -base64 32` (documented in .env.example from 01-01); Auth.js handles token rotation/expiry/replay |
</threat_model>
