## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram worker → PostGIS SQL | Worker-supplied lon/lat flow into `snapToRoute`'s SQL. Untrusted numeric input crossing into a database query. |
| snapToRoute → outer transaction | A geo failure must not escape into the submission insert's transaction (best-effort boundary). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04 | Tampering (SQL injection) | snapToRoute lon/lat/flowId | mitigate | All coordinate and flow_id values bind through Drizzle `sql\`\`` template parameters (`${lon}`, `${lat}`, `${flowId}`) — prepared-statement bindings, never string concatenation. Task 1 acceptance gate greps for `ST_MakePoint(${lon}` to enforce parameterized form. (security_requirement: parameterized PostGIS bindings.) |
| T-04-05 | Denial of Service (degenerate geometry) | PostGIS snap on malformed/edge-case linestrings | mitigate | snapToRoute is wrapped in try/catch (D-42); a degenerate route or invalid geometry that throws inside PostGIS degrades to location_match='no_route' rather than aborting the submission or hanging the transaction. PostGIS (not hand-rolled JS) handles antimeridian/duplicate-point edge cases per RESEARCH §Don't Hand-Roll. |
| T-04-06 | Repudiation (silent warning drop) | best-effort snap masking a real 'far' anomaly | mitigate | The best-effort catch only ever downgrades to 'no_route' (a neutral, visible state surfaced in the auditor caption by Plan 04) — it never silently sets 'near'. A failure is therefore always visible to the auditor, so D-42's tolerance cannot be exploited to hide a distance anomaly (security_requirement: best-effort snap cannot silently drop the warning). The GEO-02 no_route test asserts this state is recorded, not swallowed. |
| T-04-07 | Tampering | PROXIMITY_THRESHOLD_M | mitigate | Threshold is a server-side env var read in `getProximityThresholdM()`; not worker-controllable and no UI override in v1 (D-45). |
| T-04-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages (RESEARCH §Package Legitimacy Audit). No checkpoint needed. |
