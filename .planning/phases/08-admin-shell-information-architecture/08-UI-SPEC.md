## Spacing Scale

Declared values (all multiples of 4, following Tailwind 4 / 8-point grid). Inherited from Phase 05:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, tight inline padding |
| sm | 8px | Compact element spacing, badge padding, sidebar item icon gap |
| md | 16px | Default element spacing, card internal padding |
| lg | 24px | Section padding, sidebar group label margin |
| xl | 32px | Layout gaps, Overview KPI card grid gap |
| 2xl | 48px | Page-level section breaks |
| 3xl | 64px | Reserved; not used in Phase 8 |

Exceptions for Phase 8:
- Sidebar width (collapsed): 56px (icon-only mode on desktop)
- Sidebar width (expanded): 240px (label + icon mode on desktop)
- Touch targets for sidebar nav items: minimum 44px height (WCAG 2.5.5 practical target)
- KPI stat number font size: 28px (`text-3xl`) — larger than the display table to communicate command-center hierarchy; this is the only place 28px is used
- Sidebar on mobile: full-width sheet drawer (off-canvas), triggered by hamburger icon in TopNav

## Typography

All sizes use Inter (`--font-sans`). Inherited from Phase 05 with one Phase-8-specific addition.

| Role | Size | Weight | Line Height | Tailwind class |
|------|------|--------|-------------|----------------|
| Body | 14px | 400 (regular) | 1.5 | `text-sm` |
| Label | 14px | 600 (semibold) | 1.4 | `text-sm font-semibold` |
| Heading | 16px | 600 (semibold) | 1.4 | `text-base font-semibold` |
| Display | 20px | 600 (semibold) | 1.2 | `text-xl font-semibold` |
| KPI stat number | 28px | 700 (bold) | 1.1 | `text-3xl font-bold` |

Rules (carried from Phase 05):
- Standard dashboard data roles use only 2 weights: 400 and 600. The KPI stat number at 700 is
  permitted only for the Overview command-center stat figures — not for any other surface.
- Numbers in KPI cards and tables: `tabular-nums` class.
- Locale formatting: `Intl.NumberFormat('tr-TR')` for quantities and counts;
  `toLocaleDateString('tr-TR')` for dates — established pattern.
- Sidebar nav label text: Body (14px / 400). Active sidebar item label: Label (14px / 600).

| Role | Token / Value | Usage |
|------|---------------|-------|
| Dominant (60%) | `--background` `oklch(0.985 0.004 264)` | Page backgrounds, main content area |

| Destructive | `--destructive` `oklch(0.577 0.245 27.325)` | Rejection count badges, delete actions only |

| Muted | `--muted-foreground` `oklch(0.5 0.022 264)` | Sidebar inactive item labels, secondary KPI labels |

**Accent reserved for (explicit list):**
1. Active sidebar navigation item background (`--sidebar-accent`) and label color (`--sidebar-accent-foreground`)
2. Active sidebar item left-border indicator (3px solid `--primary` at left edge)
3. Primary CTA buttons (e.g. "Genel Bakış'a Git" redirect, future phase actions)
4. Focus ring (`--ring`)
5. Progress bars if reused from Phase 05

**Accent is NOT used for:** sidebar inactive items, KPI card backgrounds, KPI icon colors in neutral state.

**Sidebar tokens in use** (already declared in globals.css):
- `--sidebar`: sidebar panel background
- `--sidebar-foreground`: nav item text
- `--sidebar-primary`: wordmark / active icon color
- `--sidebar-accent`: active nav item background fill
- `--sidebar-accent-foreground`: active nav item label color
- `--sidebar-border`: sidebar right border
- `--sidebar-ring`: focus ring within sidebar

## Layout & Interaction Patterns

### Route group structure (UX-01 / additive IA decision from ROADMAP.md)

```
src/app/dashboard/
  layout.tsx                     ← existing — TopNav auth guard (UNCHANGED)
  page.tsx                       ← NEW — redirect to /dashboard/overview
  (admin)/
    layout.tsx                   ← NEW — admin shell: Sidebar + <main> content area
    overview/
      page.tsx                   ← NEW — cross-project command-center
    people/
      page.tsx                   ← NEW — people list
      [personId]/
        page.tsx                 ← NEW — person profile
  projects/                      ← EXISTING — untouched
    page.tsx
    [id]/
      page.tsx
```

The `(admin)` route group is a parallel layout. Routes under it receive the sidebar shell.
Existing `/dashboard/projects/*` routes do NOT move and do NOT get the sidebar layout.
The Projects sidebar item links to `/dashboard/projects` — the existing route.

### Redirect: /dashboard → /dashboard/overview

`src/app/dashboard/page.tsx` contains a single `redirect('/dashboard/overview')` call.
No HTML rendered. This satisfies Success Criterion 1.

### Admin shell layout: Sidebar + content

`src/app/dashboard/(admin)/layout.tsx` wraps children in the shadcn `<SidebarProvider>`
with a `<Sidebar>` on the left and a `<SidebarInset>` content area on the right.

**Desktop layout:**
- Sidebar: 240px expanded / 56px collapsed (icon-only), left-anchored, `sticky top-14`
  (below the existing TopNav at `h-14`)
- Content: fills remaining width, `max-w-5xl mx-auto px-6 py-8` — matching existing
  dashboard page padding

**Mobile layout (< 768px):**
- Sidebar becomes an off-canvas Sheet drawer
- A hamburger icon (`Menu` from lucide-react, 20px) is injected into the TopNav right
  section via the `<SidebarTrigger>` component — placed left of the LanguageToggle
- No layout shift on mobile: content takes full width, sidebar is hidden until triggered

### Sidebar navigation structure (UX-01)

Six items in order. Each item has an icon (lucide-react) and a localized label.

| Order | Label (EN) | Label (TR) | Icon | Route | Notes |
|-------|-----------|------------|------|-------|-------|
| 1 | Overview | Genel Bakış | `LayoutDashboard` | `/dashboard/overview` | Default landing |
| 2 | Projects | Projeler | `FolderOpen` | `/dashboard/projects` | Links to EXISTING route |
| 3 | People | Personel | `Users` | `/dashboard/people` | New Phase 8 page |
| 4 | Analytics | Analizler | `BarChart2` | `/dashboard/analytics` | Stub page — Phase 9 builds this |
| 5 | Hakkediş | Hakkediş | `FileText` | `/dashboard/hakedis` | Stub page — Phase 10 builds this |
| 6 | Exports | Dışa Aktar | `Download` | `/dashboard/exports` | Stub page — Phase 11 builds this |

**Active item detection:** `usePathname()` in a `'use client'` `<SidebarNav>` component.
An item is active when `pathname === item.href` (exact match for `/dashboard/overview`, `/dashboard/people`)
or `pathname.startsWith(item.href)` for routes with sub-pages (`/dashboard/projects/*`).

**Active item visual treatment:**
- Background: `--sidebar-accent` fill on the item row
- Left border: 3px solid `--primary` on the left edge of the nav item
- Label: `--sidebar-accent-foreground` (Industrial Blue tone)
- Icon: `--sidebar-accent-foreground`

**Inactive item visual treatment:**
- No background
- Label and icon: `--sidebar-foreground` (muted)
- Hover: `--sidebar-accent` fill at 50% opacity (Tailwind: `hover:bg-sidebar-accent/50`)

**Stub pages (Analytics, Hakkediş, Exports):** Each renders a minimal page with a heading,
a `<Badge variant="secondary">` showing "Coming soon" / "Yakında", and a muted body paragraph.
These pages make the routes reachable (no 404) without implementing Phase 9–11 functionality.

### Overview page — KPI command center (UX-02)

`export const dynamic = 'force-dynamic'` — financial data, never cached.

Data source: `getPortfolioOverview()` (returns `ProjectSummary[]`) and `getPortfolioKPIs()`
— a new slim function reading pending backlog count, 30-day approval/rejection counts,
and active worker count. These are lightweight queries on existing indexed columns.

**Page layout:**

```
┌──────────────────────────────────────────────────────────────────────┐
│  Page heading: "Genel Bakış" / "Overview"  (Display, text-xl/600)   │
│  Subtitle: "Son 30 günlük portföy özeti" / "30-day portfolio summary"│
├──────────────────────────────────────────────────────────────────────┤
│  KPI card row (4 cards, CSS grid 2-col mobile / 4-col desktop)       │
│  ┌────────────┐ ┌────────────┐ ┌────────────┐ ┌────────────┐       │
│  │ Onay       │ │ Ret        │ │ Bekleyen   │ │ Aktif İşçi │       │
│  │ Bekleyen   │ │ (30 gün)   │ │ Backlog    │ │ Sayısı     │       │
│  │ [stat num] │ │ [stat num] │ │ [stat num] │ │ [stat num] │       │
│  └────────────┘ └────────────┘ └────────────┘ └────────────┘       │
├──────────────────────────────────────────────────────────────────────┤
│  Earned Value section heading                                         │
│  Per-project EV vs BAC table (or card list on mobile)                │
│  (grouped by currency — one row/card per project per currency)       │
└──────────────────────────────────────────────────────────────────────┘
```

**KPI card anatomy:**
Each card uses shadcn `<Card>` with `<CardHeader>` and `<CardContent>`:
- Icon (lucide, 20px, `text-muted-foreground`) — top-left of header
- Label (Body 14px / 400, `text-muted-foreground`) — card header
- Stat number (28px / 700, `tabular-nums`) — card content, prominent
- Optional sub-label (Body 12px / 400, muted) e.g. "son 30 gün" / "last 30 days"

| KPI | Icon | EN label | TR label | Stat color rule |
|-----|------|----------|----------|-----------------|
| Pending backlog (pending_audit count) | `Clock` | "Pending Audits" | "Bekleyen Denetim" | `--destructive` if > 20, else `--foreground` |
| Approvals (last 30 days) | `CheckCircle2` | "Approvals (30d)" | "Onaylar (30 gün)" | success emerald |
| Rejections (last 30 days) | `XCircle` | "Rejections (30d)" | "Retler (30 gün)" | destructive red |
| Active workers | `HardHat` | "Active Workers" | "Aktif İşçiler" | `--foreground` |

**Earned Value table (per-project, per-currency):**
Below the KPI row. Uses shadcn `<Table>`.

| Column | Content | Notes |
|--------|---------|-------|
| Project | Project name, linked to `/dashboard/projects/[id]` | `hover:underline` |
| Contracted (BAC) | `Σ planned_qty × unit_price` formatted as `decimal.js` + currency code | Per currency row |
| Earned Value (EV) | `Σ approved_qty × unit_price` same format | Per currency row |
| % Complete | `EV / BAC × 100` formatted to 1 decimal | shadcn `<Progress>` bar inline (h-2) + number |
| Currency | ISO-4217 code (TRY / USD / EUR) | Visible column — not hidden |

Currency grouping: if a project has BOQ items in multiple currencies, it renders one table
row per currency. A project with zero unit prices renders a row with "—" in value columns
and no progress bar. Numbers use `Intl.NumberFormat('tr-TR', {minimumFractionDigits:2, maximumFractionDigits:2})`.

Empty state (no projects with any data): Icon (`LayoutDashboard`, 48px, muted) + text
"Henüz proje verisi yok." / "No project data yet."

### People list page — /dashboard/people (PERF-04)

`export const dynamic = 'force-dynamic'`

Data source: `getPersonMetrics()` with `asAuditor: false` for workers and `asAuditor: true`
for auditors — called in parallel via `Promise.all`.

**Page layout:**
- Page heading: "Personel" / "People"
- Tab bar: "İşçiler" / "Workers" | "Denetçiler" / "Auditors"
  (Uses existing shadcn `<Tabs>` component; URL state `?role=worker|auditor`)
- Table with rows linking to `/dashboard/people/[personId]`

**People list table columns (workers tab):**

| Column | Content |
|--------|---------|
| Name | Linked to profile page (`hover:underline`) |
| Submissions | `submissionsApproved + submissionsRejected + submissionsPending` total count |
| Approved | `submissionsApproved` — success badge |
| Rejected | `submissionsRejected` — destructive badge |
| Pending | `submissionsPending` — secondary badge |
| Value Contributed | Per-currency map; renders stacked lines if multi-currency; "—" if no prices set |

**People list table columns (auditors tab):**

| Column | Content |
|--------|---------|
| Name | Linked to profile page (`hover:underline`) |
| Decisions | `decisionsCount` |
| Avg Turnaround | `avgDecisionLatencyHours` formatted as "X.X h"; null → "—" |
| Pending Backlog | `pendingBacklogCount` — warning badge if > 5 |

Empty state: Icon (`Users`, 48px, muted) + "Henüz personel yok." / "No people yet."

### Person profile page — /dashboard/people/[personId]

`export const dynamic = 'force-dynamic'`

Data source: `getPersonMetrics(personId, { asAuditor: false })` and (if person has
auditor assignment) `getPersonMetrics(personId, { asAuditor: true })`.

**Page layout:**
- Back link: "← Personel" / "← People" linking to `/dashboard/people`
- Person name as page heading (Display, 20px/600)
- KPI stat row (same 4-card grid pattern as Overview, subset of metrics relevant to person)
- Activity section: placeholder card "Detaylı aktivite analizi Phase 9'da eklenecek." /
  "Detailed activity analytics will be added in Phase 9." with `<Badge variant="secondary">Coming in Phase 9</Badge>`

**Person KPI cards:**

| KPI | Worker | Auditor |
|-----|--------|---------|
| Stat 1 | Approved submissions | Decisions made |
| Stat 2 | Rejection rate (`rejected / total decided × 100`) % | Approval rate (`approved / total × 100`) % |
| Stat 3 | Location compliance rate (%) | Avg turnaround (hours) |
| Stat 4 | Value contributed (per currency, stacked if multi) | Pending backlog |

If the person has neither worker nor auditor assignments, display an `<Alert>` with message
"Bu kişinin henüz tamamlanmış bir kaydı yok." / "This person has no completed records yet."

## Accessibility

Inherits all rules from Phase 05-UI-SPEC.md. Phase 8 additions:

- Sidebar nav items: `aria-current="page"` on the active item's `<a>` element.
- Sidebar collapse button: `aria-label="Collapse sidebar"` / `aria-label="Expand sidebar"` (EN);
  `aria-label="Kenar çubuğunu daralt"` / `aria-label="Kenar çubuğunu genişlet"` (TR).
- Mobile sidebar sheet: focus is trapped inside when open; Escape closes it (shadcn Sheet default).
- KPI cards: stat numbers are in `<dd>` elements with associated `<dt>` labels (definition list semantics inside each card's CardContent).
- Sidebar nav list: `<nav aria-label="Main navigation">` wrapping the `<ul>` of items.
- Color alone is never the only signal: KPI pending-audit card uses both color change AND an icon badge when threshold is exceeded.
