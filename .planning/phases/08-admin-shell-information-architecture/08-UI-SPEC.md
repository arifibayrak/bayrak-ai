## Spacing Scale

Declared values (all multiples of 4, following Tailwind 4 / 8-point grid). Inherited from Phase 05:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, tight inline padding |
| sm | 8px | Compact element spacing, badge padding, sidebar item icon gap |
| md | 16px | Default element spacing, card internal padding |
| lg | 24px | Section padding, sidebar group label margin |
| xl | 32px | Layout gaps, Overview KPI card grid gap |
| 2xl | 48px | Page-level section breaks |
| 3xl | 64px | Reserved; not used in Phase 8 |

Exceptions for Phase 8:
- Sidebar width (collapsed): 56px (icon-only mode on desktop)
- Sidebar width (expanded): 240px (label + icon mode on desktop)
- Touch targets for sidebar nav items: minimum 44px height (WCAG 2.5.5 practical target)
- KPI stat number font size: 28px (`text-3xl`) — larger than the display table to communicate command-center hierarchy; this is the only place 28px is used
- Sidebar on mobile: full-width sheet drawer (off-canvas), triggered by hamburger icon in TopNav
- Filter bar height: 48px row (8px internal padding top/bottom + 32px input height)
- Chart container height: 240px (desktop), 180px (mobile) — consistent across all trend chart instances
- Activity timeline item: min 44px touch target per row entry

## Typography

All sizes use Inter (`--font-sans`). Inherited from Phase 05 with the Phase-8-specific KPI
addition (already in v1 spec). Exactly 4 distinct pixel sizes and exactly 2 weights across
this entire phase.

| Role | Size | Weight | Line Height | Tailwind class |
|------|------|--------|-------------|----------------|
| Body | 14px | 400 (regular) | 1.5 | `text-sm` |
| Label | 14px | 600 (semibold) | 1.4 | `text-sm font-semibold` |
| Heading | 16px | 600 (semibold) | 1.4 | `text-base font-semibold` |
| Display | 20px | 600 (semibold) | 1.2 | `text-xl font-semibold` |
| KPI stat number | 28px | 600 (semibold) | 1.1 | `text-3xl font-semibold` |

Rules (carried from Phase 05):
- All text uses exactly 2 weights: 400 (regular) and 600 (semibold). No weight 700 anywhere.
- The 28px KPI stat number uses 600; its size alone provides sufficient visual dominance.
- Numbers in KPI cards, tables, charts: `tabular-nums` class.
- Locale formatting: `Intl.NumberFormat('tr-TR')` for quantities and counts; `toLocaleDateString('tr-TR')` for dates.
- Sidebar nav label text: Body (14px / 400). Active sidebar item label: Label (14px / 600).
- Chart axis labels and tick marks: Body (14px / 400), `text-muted-foreground`.
- Filter bar input labels: Label (14px / 600).
- Timeline entry date/time: Body (14px / 400), `text-muted-foreground`.
- Timeline entry description: Body (14px / 400).

> Note on distinct sizes: Body and Label both sit at 14px — the split is weight, not size.
> The 4 distinct pixel sizes in use are 14, 16, 20, and 28.

## Layout & Interaction Patterns

### Shell coverage correction (D-64 — OVERRIDES v1 UI-SPEC assumption)

**Decision D-64 explicitly overrides the v1 spec's (admin)-only sidebar assumption.**
The sidebar wraps ALL dashboard pages, including the existing `/dashboard/projects/*` routes.
Implementation approach: add sidebar rendering directly to `src/app/dashboard/layout.tsx`
(the shared root dashboard layout), so both projects and admin pages inherit it without
moving any existing files.

The `(admin)` route group still exists as an organizational grouping for new admin pages,
but it no longer acts as the sole sidebar provider.

### Route structure (additive — no existing routes moved or renamed)

```
src/app/dashboard/
  layout.tsx                      ← MODIFIED — add SidebarProvider + Sidebar here (D-64)
  page.tsx                        ← NEW — redirect('/dashboard/overview')
  (admin)/
    layout.tsx                    ← NEW — thin layout passthrough (no double sidebar)
    overview/
      page.tsx                    ← NEW — filterable cross-project command-center
    people/
      page.tsx                    ← NEW — cross-project people directory
      [personId]/
        page.tsx                  ← NEW — person profile + activity timeline
    analytics/
      page.tsx                    ← NEW — stub page (Phase 9)
    hakedis/
      page.tsx                    ← NEW — stub page (Phase 10)
    exports/
      page.tsx                    ← NEW — stub page (Phase 11)
  records/
    page.tsx                      ← NEW — cross-project filterable records list (D-74)
    [id]/
      page.tsx                    ← NEW — canonical submission detail page (D-71)
  projects/                       ← EXISTING — untouched page files; inherits sidebar via root layout
    page.tsx
    [id]/
      page.tsx
```

Note: `/dashboard/records` and `/dashboard/records/[id]` live outside `(admin)` because
they are also reachable via drill-down from the existing project Kayıtlar tab (D-72) and
having them outside the group avoids nested layout complications.

### Redirect: /dashboard → /dashboard/overview

`src/app/dashboard/page.tsx` contains a single `redirect('/dashboard/overview')` call.
No HTML rendered. Satisfies Success Criterion 1.

### Admin shell layout: Sidebar + content

`src/app/dashboard/layout.tsx` is modified to wrap children in `<SidebarProvider>`
with a `<Sidebar>` on the left and a `<SidebarInset>` content area on the right.

**Desktop layout:**
- Sidebar: 240px expanded / 56px collapsed (icon-only), left-anchored, `sticky top-0 h-screen`
- Content: fills remaining width, `max-w-5xl mx-auto px-6 py-8` — matching existing page padding
- TopNav renders inside `<SidebarInset>` header slot, full width

**Mobile layout (< 768px):**
- Sidebar becomes an off-canvas Sheet drawer
- A hamburger icon (`Menu` from lucide-react, 20px) is injected into the TopNav left
  section via `<SidebarTrigger>` — placed left of the app wordmark/logo
- No layout shift on mobile; content takes full width; sidebar is hidden until triggered

### Sidebar navigation structure (UX-01)

Six items in order. Each item has an icon (lucide-react) and a localized label.

| Order | Label (EN) | Label (TR) | Icon | Route | Notes |
|-------|-----------|------------|------|-------|-------|
| 1 | Overview | Genel Bakış | `LayoutDashboard` | `/dashboard/overview` | Default landing |
| 2 | Projects | Projeler | `FolderOpen` | `/dashboard/projects` | Links to EXISTING route |
| 3 | People | Personel | `Users` | `/dashboard/people` | New Phase 8 page |
| 4 | Analytics | Analizler | `BarChart2` | `/dashboard/analytics` | Stub — Phase 9 builds this |
| 5 | Hakkediş | Hakkediş | `FileText` | `/dashboard/hakedis` | Stub — Phase 10 builds this |
| 6 | Exports | Dışa Aktar | `Download` | `/dashboard/exports` | Stub — Phase 11 builds this |

`/dashboard/records` has NO sidebar item (D-74). It is drill-only.

**Active item detection:** `usePathname()` in a `'use client'` `<SidebarNav>` component.
An item is active when `pathname === item.href` (exact for `/dashboard/overview`, `/dashboard/people`)
or `pathname.startsWith(item.href)` for routes with sub-pages (`/dashboard/projects/*`,
`/dashboard/people/*`). The `records` list and detail page have no corresponding sidebar item.

**Active item visual treatment:**
- Background: `--sidebar-accent` fill on the item row
- Left border: 3px solid `--primary` on the left edge of the nav item
- Label: `--sidebar-accent-foreground` (Industrial Blue tone)
- Icon: `--sidebar-accent-foreground`

**Inactive item visual treatment:**
- No background fill
- Label and icon: `--sidebar-foreground` (muted)
- Hover: `--sidebar-accent` fill at 50% opacity (`hover:bg-sidebar-accent/50`)

**Stub pages (Analytics, Hakkediş, Exports):** Each renders a minimal page with a heading,
a `<Badge variant="secondary">` showing "Coming soon" / "Yakında", and a muted body paragraph.
Routes are reachable (no 404) without implementing Phase 9–11 functionality.

## Global Filter Bar (UX-03)

### Filter parameters

URL query parameters that persist across navigation and scope all filterable pages
(Overview, People directory, People profile, Records list).

| Param | Type | Default | Values |
|-------|------|---------|--------|
| `from` | ISO-8601 date string | (omitted = all time) | e.g. `2026-01-01` |
| `to` | ISO-8601 date string | (omitted = all time) | e.g. `2026-05-31` |
| `project` | project UUID | (omitted = all projects) | single project ID |
| `person` | person UUID | (omitted = all people) | single person ID |
| `status` | `pending_audit` \| `approved` \| `rejected` | (omitted = all statuses) | Records list only |

Date boundaries use Istanbul timezone (AT TIME ZONE 'Europe/Istanbul') in Postgres queries.
Default date range is all time — no date bound applied when `from`/`to` are absent.

### Filter bar component anatomy

The filter bar is a sticky horizontal row at the top of each filterable page's content area
(not shell-global). It renders above the page content, below the page heading.

Layout: single row on desktop, stacked 2×2 grid on mobile.

| Control | Component | Width (desktop) |
|---------|-----------|----------------|
| Date range: From | `<Input type="date">` | 160px |
| Date range: To | `<Input type="date">` | 160px |
| Project | `<Select>` (project list) | 200px |
| Person | `<Select>` (people list) | 200px |
| Clear filters | `<Button variant="ghost" size="sm">` | auto |

The Currency Selector is a separate control (see below) — it is NOT a filter param but a
display preference. It lives adjacent to the filter bar on money-showing pages (Overview).

### URL persistence behavior

Links from filterable pages propagate the current filter params to their destination.
Navigation via the sidebar discards the params (user is starting a new context).
The Clear filters button navigates to the current page URL with no query params.

### Filter bar labels (localized)

| Control | EN label | TR label |
|---------|----------|----------|
| From date | "From" | "Başlangıç" |
| To date | "To" | "Bitiş" |
| Project | "All Projects" (placeholder) | "Tüm Projeler" |
| Person | "All People" (placeholder) | "Tüm Personel" |
| Clear | "Clear filters" | "Filtreleri temizle" |

## Currency Selector (D-67)

A single `<Select>` control displayed adjacent to the filter bar on Overview and any other
page showing money values. Default value: TRY.

**Behavior:**
- Governs all money displays on the current page (KPI cards, EV table, trend charts)
- State is local to the page — NOT a URL query param (it is a display preference, not a data filter)
- Projects/BOQ items with no data in the selected currency show "—" in all value cells
- Each currency is aggregated separately in Postgres; the selector picks which result set to render

**Component:** `<Select>` from shadcn with options built from the set of distinct `currency_code`
values across all BOQ items in the tenant. The option set is always at least `["TRY"]`.

**Visual treatment:**
- Placed right-aligned in the same row as the filter bar, or as a standalone control above
  the Earned Value table if the filter bar is not present on that page.
- Width: 100px (fits 3-char ISO codes with selector arrow).
- Label (EN): "Currency" / (TR): "Para Birimi" — placed as a visually small label above the select.

## Accessibility

Inherits all rules from Phase 05-UI-SPEC.md. Phase 8 additions:

- Sidebar nav items: `aria-current="page"` on the active item's `<a>` element.
- Sidebar collapse button: `aria-label="Collapse sidebar"` / `"Expand sidebar"` (EN);
  `"Kenar çubuğunu daralt"` / `"Kenar çubuğunu genişlet"` (TR).
- Mobile sidebar sheet: focus is trapped inside when open; Escape closes it (shadcn Sheet default).
- KPI cards: stat numbers are in `<dd>` elements with associated `<dt>` labels (definition list semantics inside each card's CardContent).
- Sidebar nav list: `<nav aria-label="Main navigation">` wrapping the `<ul>` of items.
- Color alone is never the only signal: KPI pending-audit card uses both color AND an icon badge when threshold is exceeded.
- Filter bar inputs: each `<Input>` has an explicit `<label>` (or `aria-label`) — not just placeholder text.
- Charts: each `<ChartContainer>` has `aria-label` describing the chart's subject (e.g. "Throughput trend chart"). Tooltip accessible via keyboard. Data table alternative not required for MVP.
- Activity timeline: `<ol>` (ordered list, newest first) with `<li>` for each entry. Month group headings use `<h3>`.
- Submission detail: `<dl>` / `<dt>` / `<dd>` semantic pairs for all field-value blocks.
- Records table: `<th scope="col">` for all header cells. The hidden "Actions" column header uses `<th class="sr-only">`.
