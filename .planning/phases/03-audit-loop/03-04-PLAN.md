<objective>
Build the auditor fan-out service and wire it to fire after the worker's confirm transaction commits. On confirm, load the submission + BOQ item + project, find all auditors assigned to that project, and send each a Telegram photo message (photo via file_id with Blob URL fallback) carrying the BOQ material+unit, quantity, notes, a Google Maps link, an over-delivery warning when applicable, and the ✅ Onayla / ❌ Reddet inline keyboard. Persist each sent message's (chat_id, message_id) in audit_notifications so Plan 05 can edit all siblings on the first decision. Handle the no-auditor edge case (D-39) and best-effort send failures (D-40).

Purpose: Delivers AUDIT-01 and AUDIT-02 — the auditor's entry point into the trust loop. Also provides `editAllSiblingMessages`, which Plan 05's decision handlers call.
Output: New `src/lib/bot-audit.ts`; one `after()` hook added to `handleConfirmSubmit` in `telegram.ts`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Worker confirm → fan-out | Submission data (notes, location) is rendered into auditor captions |
| App → Telegram API | Outbound sends may fail; failures must not corrupt state or block the worker |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-FANOUT-01 | Denial of Service | webhook synchronous path | mitigate | Fan-out runs in `after()` (or documented direct-await fallback) AFTER the worker's 200/reply; a slow or failing send never blocks the worker (RESEARCH Pitfall 6, D-40). |
| T-3-FANOUT-02 | Denial of Service | one failing auditor send | mitigate | Per-auditor try/catch; failure logged + recorded as send_failed=true; other auditors still notified (D-40). |
| T-3-FANOUT-03 | Information Disclosure | wrong-recipient targeting | mitigate | Auditors resolved by `assignments role_on_project='auditor'` on the submission's project only — never a broadcast (D-33). |
| T-3-FANOUT-04 | Repudiation/Loss | stranded submission with no auditor | mitigate | D-39: no-auditor case keeps submission pending_audit + logs a warning; never silently dropped, never a worker-facing error. |
| T-3-INJ-01 | Tampering | worker notes in caption (prompt-injection) | accept | Notes rendered as plain text in the caption; no AI/LLM consumes them in Phase 3 (AI is Phase 6). Low risk for v1. |
| T-3-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages (RESEARCH.md Package Legitimacy Audit: none). |
