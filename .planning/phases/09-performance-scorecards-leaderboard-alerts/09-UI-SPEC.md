## Color

Inherited from Phase 8. No new tokens introduced. Phase 9 establishes alert-specific color usage rules
for the existing semantic tokens.

| Role | Token / Value | Usage |
|------|---------------|-------|
| Dominant (60%) | `--background` `oklch(0.985 0.004 264)` | Page backgrounds |
| Secondary (30%) | `--card` `oklch(1 0 0)` / `--sidebar` | Cards, sidebar |
| Accent (10%) | `--primary` `oklch(0.55 0.2 255)` | See inherited reserved list — NOT used for alert badges |
| Destructive | `--destructive` `oklch(0.577 0.245 27.325)` | KpiCard alert badges (warning threshold breached), rank-1 badge background — see rules below |
| Success | `oklch(0.53 0.17 145)` (emerald) | SLA-breach rate = 0% indicator, healthy KPI state |
| Warning | `oklch(0.7 0.18 70)` (amber) | Pending-backlog caution (≤48h threshold, not yet breached) |
| Muted | `--muted-foreground` | Section labels, scorecard sub-labels, leaderboard rank text below #1 |

### Alert color semantics (NEW in Phase 9)

Alert badges on KpiCards use `--destructive` (red) or `warning` (amber), NEVER `--primary` (accent blue). This is a hard rule.

| Alert type | Color token | Condition |
|-----------|-------------|-----------|
| Pending backlog — SLA breached | `--destructive` (red `<Badge>`) | `pendingBacklog > 0` AND avg latency > `auditSlaHours` |
| Pending backlog — caution | `warning` (amber `<Badge>`) | `pendingBacklog > 0` AND avg latency not yet breached |
| Rejection-rate alert | `--destructive` (red `<Badge>`) | `rejectionRate > rejectionRateThreshold` in active filter window only |
| Stalled projects — breached | `--destructive` (red `<Badge>`) | `stalledCount >= 1` |
| SLA-breach rate on auditor scorecard | `--destructive` when > 20%; `warning` when 10–20%; success when < 10% | see auditor scorecard section |
| Healthy / no alert | no badge rendered | condition not met |

Rejection-rate alert badge: suppressed entirely when no date filter is active (all-time view). When suppressed, the Rejections KPI card shows its normal `--foreground` stat color.

### Leaderboard rank badge colors

- Rank 1: `<Badge>` with `--primary` background (accent — this IS one of the 6 reserved accent uses, added in Phase 9)
- Rank 2–3: `<Badge variant="secondary">`
- Rank 4+: plain rank number, no badge, `text-muted-foreground`

This adds one item to the Phase 8 accent reserved list:

**Updated accent reserved list (7 elements):**
1. Active sidebar navigation item background and label color
2. Active sidebar item left-border indicator (3px solid `--primary`)
3. Primary CTA buttons
4. Focus ring (`--ring`)
5. Progress bars (from Phase 5)
6. Currency selector trigger border when focused
7. **Rank-1 badge background in leaderboard** (Phase 9 addition)

## Layout & Interaction Patterns

### Surface 1: Enriched Person Profile Page — /dashboard/people/[personId]

Extends the Phase 8 profile page. The Phase 8 layout is preserved; new metric cards are added.

#### Worker scorecard additions (PERF-01)

The existing 4-card KPI row gains 2 additional cards. Layout becomes a 6-card grid (3-col desktop / 2-col mobile) when person is worker-only. When person has both roles, layout is two groups of cards separated by `<Separator>`.

**New KPI cards for workers:**

| Card # | Metric | Icon | EN label | TR label | Value format | Color rule |
|--------|--------|------|----------|----------|--------------|------------|
| 5 | Output quantity sum (approved submissions) | `Package` | "Output Volume" | "Çıktı Hacmi" | `{sum} {unit}` — unit from the most common BOQ item unit, or "units" if mixed | `--foreground` |
| 6 | Approval rate | `TrendingUp` | "Approval Rate" | "Onay Oranı" | `X.X%` — `(approved / (approved + rejected)) × 100` | success (emerald) if ≥ 80%, `--foreground` if 50–79%, destructive if < 50% |

The existing Phase 8 worker cards (approved count, rejection rate, location compliance, value contribution) are preserved in positions 1–4.

**Throughput display:** rendered as a sub-label on the "Output Volume" card when date range is active: "X.XX per day" / "günde X.XX". Hidden (sub-label shows "—") when no date filter is set.

#### Auditor scorecard additions (PERF-02)

The existing 4-card auditor KPI row gains 1 additional card. Layout becomes 5 cards (3+2 on desktop / 2-col mobile).

**New KPI card for auditors:**

| Card # | Metric | Icon | EN label | TR label | Value format | Color rule |
|--------|--------|------|----------|----------|--------------|------------|
| 5 | SLA-breach rate | `AlertTriangle` | "SLA Breach Rate" | "SLA İhlal Oranı" | `X.X%` — `(breached decisions / total decided) × 100` | destructive if > 20%; `oklch(0.7 0.18 70)` (amber) if 10–20%; success if < 10%; "—" if no decided submissions |

The `AlertTriangle` icon itself uses the same color class as the value (not `text-muted-foreground`) to reinforce the severity signal.

#### Dual-role scorecard layout

When a person is both worker and auditor, the profile page renders:
```
<h2 class="text-base font-semibold mt-6 mb-3">Worker Metrics / İşçi Metrikleri</h2>
[6-card worker grid]
<Separator class="my-6" />
<h2 class="text-base font-semibold mt-6 mb-3">Auditor Metrics / Denetçi Metrikleri</h2>
[5-card auditor grid]
```

#### Per-project vs all-projects scoping

Controlled by the existing Phase 8 `project` URL param on the FilterBar. No new UI element needed. When a project is selected, each KPI card's sub-label shows "in {projectName}" / "{projeAdında}". When no project is selected (all projects), sub-label shows "across all projects" / "tüm projelerde".

#### PERF-03 office-engineer parity note (D-80)

Add an informational `<Alert>` in the People directory (`/dashboard/people`) — visible only when viewing the office engineer's profile — as a navigation affordance:

```
<Alert variant="secondary" className="mt-4">
  <Info className="h-4 w-4" />
  <AlertDescription>
    EN: "Office engineer activity is tracked in the Analytics section."
    TR: "Ofis mühendisi aktivitesi Analizler bölümünde izlenmektedir."

This note only appears if the viewed person's role on project is not worker or auditor (i.e. they are an office engineer). Given office engineers live in `users` not `people`, this edge case may not be reachable via the current data model — implement as a no-op guard that renders the note only when `metrics.workerRole === false && metrics.auditorRole === false`. Planner may scope this to a non-functional note if data model prevents the condition.

Not applicable — the rank column is always shown in Phase 9. There is no separate "directory mode" toggle.

### Surface 4: /dashboard/settings — Threshold Form (PERF-06 / D-83/84/85/86/89)

A new dedicated page. No sidebar item (D-86). Reachable via a gear icon in TopNav (see entry point below).

#### Entry point

`TopNav.tsx` gains a gear icon button (`Settings` from lucide-react, 20px) placed to the right of the LanguageToggle, with 8px left margin. It is an `<a href="/dashboard/settings">` (not a `<Button>` — it's a navigation link, rendered as `<Link href="/dashboard/settings">`).

Aria-label: `"Open settings"` / `"Ayarları aç"`.

The settings icon has NO label text — icon only. It uses `text-muted-foreground` at rest, `text-foreground` on hover.

#### Page layout

```
Page heading: "Settings" / "Ayarlar" — Display (20px / 600)
Subtitle: "Performance alert thresholds" / "Performans uyarı eşikleri" — Body (14px / 400, muted)

<Card> containing the form
  <CardHeader>
    <CardTitle>Alert Thresholds / Uyarı Eşikleri — Heading (16px / 600)
  </CardHeader>
  <CardContent>
    [3 form rows — see below]
    <Button type="submit"> "Save" / "Kaydet"

#### Form anatomy

Three numeric input rows, vertically stacked with 24px gap between rows. Each row:
- `<Label>` (14px / 600) — above the input
- Description (14px / 400, muted) — below the label, above the input
- `<Input type="number">` — 120px wide on desktop, full-width on mobile
- Unit annotation — inline, 8px left of input, Body (14px / 400, `text-muted-foreground`)

| Field | EN label | TR label | EN description | TR description | Unit | Min | Max | Default |
|-------|----------|----------|----------------|----------------|------|-----|-----|---------|
| Audit pending SLA | "Audit SLA Threshold" | "Denetim SLA Eşiği" | "Alert when pending audits exceed this many hours" | "Bekleyen denetimler bu saati geçerse uyar" | hours / saat | 1 | 720 | 48 |
| Rejection rate | "Rejection Rate Alert" | "Red Oranı Uyarısı" | "Alert when rejection rate exceeds this percentage" | "Red oranı bu yüzdeyi geçerse uyar" | % | 0 | 100 | 30 |
| Stalled project days | "Stalled Project Threshold" | "Durma Eşiği" | "Alert when a project has no approvals for this many days" | "Bir proje bu kadar gün onaysız kalırsa uyar" | days / gün | 1 | 365 | 7 |

> Note: rejection rate is stored as a decimal (0–1) in the DB but displayed and entered as a percentage (0–100) in the UI. The form converts on submit: `rejectionRateThreshold = input / 100`.

**Input affordances:**
- `<Input type="number" min={min} max={max} step={1}>` for hours and days
- `<Input type="number" min={0} max={100} step={1}>` for rejection rate %
- `placeholder=""` — no placeholder (value is pre-populated from DB)
- Each input is pre-populated with the current saved threshold on page load

#### Validation rules and error copy

Client-side validation runs on submit (before server action is called). Server-side Zod validation runs in the server action regardless.

| Field | Validation | EN error message | TR error message |
|-------|-----------|------------------|------------------|
| Audit SLA | Integer, 1–720 | "Audit SLA must be between 1 and 720 hours." | "Denetim SLA'sı 1 ile 720 saat arasında olmalıdır." |
| Rejection rate | Integer, 0–100 | "Rejection rate must be between 0% and 100%." | "Red oranı %0 ile %100 arasında olmalıdır." |
| Stalled days | Integer, 1–365 | "Stalled threshold must be between 1 and 365 days." | "Durma eşiği 1 ile 365 gün arasında olmalıdır." |

Error messages rendered below the relevant input in `text-sm text-destructive` (14px / 400, red). No inline error icons.

#### Success feedback

On successful save: an `<Alert>` component replaces the form's submit button area for 3 seconds:
- `<Alert>` with `CheckCircle2` (16px) icon and text "Settings saved." / "Ayarlar kaydedildi."
- After 3 seconds the alert disappears and the submit button returns to normal state
- The form fields retain their (saved) values — no reset

This is a transient success message, not a persistent toast. No toast component install needed.

#### Auth guard behavior

If a non-office-engineer user somehow reaches `/dashboard/settings`, the RSC calls `auth()` and the server action enforces the same guard. The page renders normally (no special "unauthorized" UI needed — the guard throws and Next.js renders its error page).

### Surface 5: Overview Alert Badges + Stalled Projects KpiCard (PERF-06 / D-87/88)

#### KpiCard row becomes 5 cards

The Overview KPI row expands from 4 to 5 cards. Grid: `grid-cols-2 md:grid-cols-3 lg:grid-cols-5`. The 5th card is the "Stalled Projects" card.

**New Stalled Projects KpiCard:**

| Property | Value |
|----------|-------|
| Icon | `PauseCircle` (lucide, 20px) |
| EN label | "Stalled Projects" |
| TR label | "Durmuş Projeler" |
| Value | `stalledCount` (integer) |
| `valueColor` | `'destructive'` if `stalledCount >= 1`, else `'default'` |

| Sub-label (healthy) | "All projects active" / "Tüm projeler aktif" |

The `drillHref` `/dashboard/projects?stalled=true` is a future filter — the Projects list does not implement stalled filtering in Phase 9. The link is present but the Projects page ignores the `stalled` param (it renders its existing list unchanged). This is intentional — the filter is wired in Phase 9 for forward compatibility.

#### Inline alert badge placement on existing KpiCards

The alert state is expressed via `valueColor` on the existing `KpiCard` props — the stat number color changes (red / amber / green). No additional badge element sits outside the KpiCard.

**Additionally:** extend `KpiCard` to accept an optional `alertBadge?: React.ReactNode` prop rendered as a small absolute-positioned badge at the card's top-right corner. This badge is a `<Badge variant="destructive">` with a `TriangleAlert` icon (12px) and no text. Used only when the alert is firing.

```
Interface extension to KpiCard:
  alertBadge?: React.ReactNode   // optional — renders at top-right of <Card>
```

Card layout change: `<Card>` gains `relative` class when `alertBadge` is present. The badge is `absolute top-2 right-2`.

**Existing KpiCard alert wiring (Phase 9 additions):**

| KpiCard | Alert condition | `valueColor` | `alertBadge` |
|---------|----------------|--------------|--------------|
| Pending Audits | `pendingBacklog > 0` AND avg latency > SLA threshold | `'destructive'` | `<TriangleAlert>` badge |
| Pending Audits | `pendingBacklog > 0` AND within threshold | `'warning'` (new) | none |
| Rejections | rejection rate > threshold AND date filter active | `'destructive'` | `<TriangleAlert>` badge |
| Rejections | no date filter OR rate ≤ threshold | `'default'` | none |
| Approvals | no alert state | `'success'` | none |
| Active Workers | no alert state | `'default'` | none |
| Stalled Projects | `stalledCount >= 1` | `'destructive'` | `<TriangleAlert>` badge |
| Stalled Projects | `stalledCount === 0` | `'default'` | none |

> `'warning'` must be added to `KpiCard`'s `ValueColor` type. Implementation: add `if (color === 'warning') return 'text-amber-600'` to `colorClass()`. This is the only KpiCard code change in Phase 9.

#### Healthy state (no alerts)

When all thresholds are within bounds, the Overview renders with no red badges. The Stalled Projects card shows "0" in `text-foreground` with "All projects active" sub-label. No explicit "all clear" banner is shown.

## Accessibility

Inherits all Phase 8 rules. Phase 9 additions:

- Settings form: each `<Input>` has an explicit `<Label>` with `htmlFor` matching the input `id`. Unit annotations are rendered as `<span aria-label="{unit}">` for screen reader clarity.
- Settings form: error messages rendered via `aria-describedby` linking input to its error `<p>`.
- Settings gear icon in TopNav: `aria-label="Open settings"` / `"Ayarları aç"` (no visible text, so aria-label is mandatory).
- Leaderboard rank column header: `<th scope="col" aria-label="Rank">` "#" (the symbol alone may not be announced correctly by all screen readers).
- Alert badges (`alertBadge` on KpiCard): `<span aria-label="Alert: threshold exceeded">` wrapping the `<TriangleAlert>` icon. Color alone is never the only signal — icon is always present with the badge.
- SLA-breach rate card: `AlertTriangle` icon has the same color as the value; its `aria-hidden="true"` since the value text conveys the severity.
- Office-engineer activity log table: `<th scope="col">` for Timestamp, Action, Context columns.
